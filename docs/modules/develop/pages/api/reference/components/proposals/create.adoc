= Create Proposal

== Input attributes

When you want to add or create data in your proposals component, you need to rely on the `ProposalAttributes` type, which has the following input fields:

[source]
----
• title       (Required) - 15-150 characters
• body        (Required) - minimum 15 characters
• address     (Optional) - physical address (requires geocoding)
• latitude    (Optional) - coordinate
• longitude   (Optional) - coordinate
• taxonomies  (Optional) - Taxonomies ids to assign to this proposal
• attachments (Optional) - List of `ProposalAttachmentAttributes`, the files to attach to the proposal
----

The `attachments` field is only accepted when the component allows attachments. Each entry has the following fields:

[source]
----
• file  (Required) - BaseUpload - the file to upload and attach
• title (Optional) - String - the title of the attachment
----

== Sample request

The `CreateProposal` mutation allows authenticated users to create new proposals in a Decidim proposals component. This mutation delegates to the existing `Decidim::Proposals::CreateProposal` command used by the controllers.

[source,graphql]
----
mutation createProposal($componentId: ID!, $input: CreateProposalInput!){
  component(id: $componentId) {
    ... on ProposalsMutation {
      createProposal(input: $input) {
        id
        title {
          translation(locale: "en")
        }
        body {
          translation(locale: "en")
        }
        address
        taxonomies{
          name {
            translation(locale: "en")
          }
          children{
            name{
              translation(locale: "en")
            }
          }
        }
      }
    }
  }
}
----

Example of submitted variables

[source,json]
----
{
  "componentId": 9,
  "input": {
    "locale": "en",
    "attributes": {
      "title": "Install Bike Lanes on Main Street",
      "body": "We propose adding dedicated bike lanes along Main Street to improve cyclist safety and encourage sustainable transportation.",
      "address": "Main Street, Barcelona, Spain",
      "latitude": 41.3851,
      "longitude": 2.1734
    }
  }
}
----

The `file` field is an upload, so a request which sends attachments has to be a
https://github.com/jaydenseric/graphql-multipart-request-spec[multipart request]:
the file variable is `null` in the `operations` payload and the uploaded file is
mapped to its path.

[source,bash]
----
curl -X POST https://example.org/api/ \
  -F 'operations={"query":"mutation ($componentId: ID!, $input: CreateProposalInput!) { component(id: $componentId) { ... on ProposalsMutation { createProposal(input: $input) { id } } } }","variables":{"componentId":9,"input":{"locale":"en","attributes":{"title":"Install Bike Lanes on Main Street","body":"We propose adding dedicated bike lanes along Main Street to improve cyclist safety and encourage sustainable transportation.","attachments":[{"file":null,"title":"Sidewalk photo"}]}}}}' \
  -F 'map={"0":["variables.input.attributes.attachments.0.file"]}' \
  -F '0=@/path/to/photo.jpg'
----

The files are checked before they are stored: the extension and the content type
detected from the contents are verified against the allowlists configured for the
role which performs the request, the size is checked against the configured
maximum, and the SVG documents which are not well formed or which contain active
content are rejected. When a check fails the blob is not created and the proposal
is not saved.

== Error Handling

The most frequent errors that can be generated by this mutation are as follows:

* xref:develop:api/reference/errors/unauthorized_mutation.adoc[Unauthorized Mutation Error - MUTATION_NOT_AUTHORIZED_ERROR]
* xref:develop:api/reference/errors/invalid_locale_error.adoc[Invalid Locale Error - INVALID_LOCALE_ERROR]
* xref:develop:api/reference/errors/validation_error.adoc[Validation Error - VALIDATION_ERROR] - when the uploaded file does not pass the file checks or when the component does not allow attachments
* xref:develop:api/reference/errors/attribute_validation_error.adoc[Attribute Validation Error - ATTRIBUTE_VALIDATION_ERROR]
* xref:develop:api/reference/errors/unauthorized_object.adoc[Unauthorized Object Error - UNAUTHORIZED_OBJECT_ERROR]
