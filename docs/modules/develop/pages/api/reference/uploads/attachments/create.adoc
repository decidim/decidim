= Create Attachments

==  Input attributes

When you want to create a Decidim attachment, you need to rely on the `AttachmentAttributes` type, which has the following input fields.

[source]
----
• collection            (optional) - AttachmentCollectionInputObject
• description           (optional) - JSON
• file                  (Required) - BaseUpload - the file to upload and attach
• title                 (Required) - JSON
• weight                (Optional) - Integer
----

== Sample request

The `CreateAttachment` mutation allows authenticated administrators to create new attachments within certain resources. This mutation uses the existing `CreateAttachment` command from the admin controller. In the below  example, we are creating an attachment bound to a `Result` type.

The `file` field is an upload, so the mutation is called with a
https://github.com/jaydenseric/graphql-multipart-request-spec[multipart request]:
the file variable is `null` in the `operations` payload and the uploaded file is
mapped to its path.

[source,graphql]
----
mutation createAttachmentMutation($componentId: ID!, $resultId: ID!, $input: CreateAttachmentInput!) {
  component(id: $componentId) {
    ... on AccountabilityMutation {
      result(id: $resultId) {
        createAttachment(input: $input) {
          id
          title {
             translation(locale: "en")
          }
          description {
            translation(locale: "en")
          }
        }
      }
    }
  }
}
----

Example of submitted variables

[source,json]
----
{
  "componentId": "3",
  "resultId": "5",
  "input": {
    "attributes": {
      "weight": 1,
      "title": {
        "en": "Your english title"
      },
      "description": {
        "en": "Your english description"
      },
      "file": null
    }
  }
}

----

The same request sent as `multipart/form-data`, with the file mapped to the
variable path:

[source,bash]
----
curl -X POST https://example.org/api/ \
  -F 'operations={"query":"mutation ($input: CreateAttachmentInput!) { createAttachment(input: $input) { id } }","variables":{"input":{"attributes":{"file":null}}}}' \
  -F 'map={"0":["variables.input.attributes.file"]}' \
  -F '0=@/path/to/file.jpg'
----

The file is checked before it is stored: the extension and the content type
detected from the contents are verified against their configured allowlists, the
size is checked against the configured maximum, and the SVG documents which are
not well formed or which contain active content are rejected. When a check fails
the blob is not created and the attachment is not saved.

== Error Handling

The most frequent errors that can be generated by this mutation are as follows:

* xref:develop:api/reference/errors/unauthorized_mutation.adoc[Unauthorized Mutation Error - MUTATION_NOT_AUTHORIZED_ERROR]
* xref:develop:api/reference/errors/invalid_locale_error.adoc[Invalid Locale Error - INVALID_LOCALE_ERROR]
* xref:develop:api/reference/errors/attribute_validation_error.adoc[Attribute Validation Error - ATTRIBUTE_VALIDATION_ERROR]
* xref:develop:api/reference/errors/validation_error.adoc[Attribute Error - VALIDATION_ERROR] - when the uploaded file does not pass the file checks
