= Create Attachments

==  Input attributes

When you want to create a Decidim attachment, you need to rely on the `AttachmentAttributes` type, which has the following input fields.

[source]
----
• collection            (optional) - Integer
• description           (optional) - JSON
• file                  (Required) - JSON - FileInputObject format
• title                 (Required) - JSON
• weight                (Optional) - Integer
----

== Sample request

The `CreateAttachment` mutation allows authenticated administrators to create new attachments within certain resources. This mutation uses the existing `CreateAttachment` command from the admin controller. In the below  example, we are creating an attachment bound to a `Result` type.

The `signedId` must be a blob which can be used by the current organization. A blob does not belong to an organization by itself, its ownership is derived from the records it is attached to, so a blob already used by records of another organization (or shared with them) is rejected with an `UNAUTHORIZED_OBJECT_ERROR`. A blob which is not attached to any record yet, as the one obtained from xref:develop:api/reference/uploads/blobs/upload.adoc[uploadFile], has no organization to check against: it is accepted and becomes owned by the record it is attached to. A `signedId` which is not a valid signature or does not match an existing blob is rejected with a `NOT_FOUND_ERROR`.

[source,graphql]
----
mutation createAttachmentMutation($componentId: ID!, $resultId: ID!, $input: CreateAttachmentInput!) {
  component(id: $componentId) {
    ... on AccountabilityMutation {
      result(id: $resultId) {
        createAttachment(input: $input) {
          id
          title {
             translation(locale: "en")
          }
          description {
            translation(locale: "en")
          }
        }
      }
    }
  }
}
----

== Error Handling

The most frequent errors that can be generated by this mutation are as follows:

* xref:develop:api/reference/errors/unauthorized_mutation.adoc[Unauthorized Mutation Error - MUTATION_NOT_AUTHORIZED_ERROR]
* xref:develop:api/reference/errors/invalid_locale_error.adoc[Invalid Locale Error - INVALID_LOCALE_ERROR]
* xref:develop:api/reference/errors/attribute_validation_error.adoc[Attribute Validation Error - ATTRIBUTE_VALIDATION_ERROR]
* xref:develop:api/reference/errors/unauthorized_object.adoc[Unauthorized Object Error - UNAUTHORIZED_OBJECT_ERROR]
* xref:develop:api/reference/errors/not_found.adoc[Not Found Error - NOT_FOUND_ERROR] - when the `signedId` is not a valid signature or does not match an existing blob
