= Update Attachments

==  Input attributes

When you want to update a Decidim attachment's details, you need to rely on the `AttachmentAttributes` type, which has the following input fields.

[source]
----
• collection            (optional) - AttachmentCollectionInputObject
• description           (optional) - JSON
• file                  (optional) - BaseUpload - the file to upload and attach
• title                 (optional) - JSON
• weight                (Optional) - Integer
----

== Sample request

The `UpdateAttachment` mutation allows authenticated administrators to update attachments within certain resources. This mutation uses the existing `UpdateAttachment` command from the admin controller. In the below example, we are updating an attachment bound to a `Result` type.

The `file` field is an upload, so a new file is sent with a
https://github.com/jaydenseric/graphql-multipart-request-spec[multipart request].
When `file` is not provided, the attachment keeps the file it already has.

[source,graphql]
----
mutation updateAttachmentMutation($componentId: ID!, $resultId: ID!, $input: UpdateAttachmentInput!) {
  component(id: $componentId) {
    ... on AccountabilityMutation {
      result(id: $resultId) {
        updateAttachment(input: $input) {
          id
          title {
            translation(locale: "en")
          }
          description {
            translation(locale: "en")
          }
        }
      }
    }
  }
}
----

Example of submitted variables

[source,json]
----
{
  "componentId": "3",
  "resultId": "5",
  "input": {
    "id":  "1234",
    "attributes": {
      "weight": 1,
      "title": {
        "en": "Your english name"
      },
      "description": {
        "en": "Your english description"
      },
      "file": null
    }
  }
}

----

The same request sent as `multipart/form-data`, with the file mapped to the
variable path:

[source,bash]
----
curl -X POST https://example.org/api/ \
  -F 'operations={"query":"mutation ($input: UpdateAttachmentInput!) { updateAttachment(input: $input) { id } }","variables":{"input":{"id":"1234","attributes":{"file":null}}}}' \
  -F 'map={"0":["variables.input.attributes.file"]}' \
  -F '0=@/path/to/file.jpg'
----

The file is checked before it is stored, in the same way as in
xref:develop:api/reference/uploads/attachments/create.adoc[Create Attachments].

== Error Handling

The most frequent errors that can be generated by this mutation are as follows:

* xref:develop:api/reference/errors/unauthorized_mutation.adoc[Unauthorized Mutation Error - MUTATION_NOT_AUTHORIZED_ERROR]
* xref:develop:api/reference/errors/invalid_locale_error.adoc[Invalid Locale Error - INVALID_LOCALE_ERROR]
* xref:develop:api/reference/errors/attribute_validation_error.adoc[Attribute Validation Error - ATTRIBUTE_VALIDATION_ERROR]
* xref:develop:api/reference/errors/validation_error.adoc[Attribute Error - VALIDATION_ERROR] - when the uploaded file does not pass the file checks
