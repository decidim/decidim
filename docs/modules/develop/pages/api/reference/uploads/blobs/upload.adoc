= Upload files

== Sample request

The `uploadFile` mutation allows authenticated administrators to upload and create file blobs.

[source,graphql]
----
mutation ($input: UploadFileInput!) {
  uploadFile(input: $input) {
    blob {
      id
      filename
      byteSize
      signedId
      checksum
    }
  }
}
----

The `uploadFile` mutation accepts a file through a multipart GraphQL request. Send the file as `multipart/form-data` using the https://github.com/jaydenseric/graphql-multipart-request-spec[GraphQL multipart request spec].

The file variable must be `null` in the `operations` payload, and the uploaded file is mapped separately:

[source,bash]
----
curl -X POST https://example.org/api/ \
  -F 'operations={"query":"mutation ($input: UploadFileInput!) { uploadFile(input: $input) { blob { id filename byteSize signedId checksum } } }","variables":{"input":{"file":null}}}' \
  -F 'map={"0":["variables.input.file"]}' \
  -F '0=@/path/to/file.jpg'
----

The uploaded blob is not attached to any record yet: pass its `signedId` to the xref:develop:api/reference/uploads/attachments/create.adoc[createAttachment] mutation to create the attachment. An upload which is never attached cannot be removed through xref:develop:api/reference/uploads/blobs/delete.adoc[deleteBlob] (a blob without attachments has no organization to authorize against); it is purged by the xref:install:index.adoc#scheduled_tasks[scheduled cleanup task] (`rake decidim:attachments_cleanup`, hourly by default), so an abandoned upload is removed once the cleanup window elapses.
