= Delete Attachment Collections

== Sample request

The `deleteAttachmentCollection` mutation allows deletion of an attachment collection when the authenticated caller is authorized for that specific collection.

Managing attachment collections is an administrative operation, so the OAuth token
used for the request must have been granted the `admin:read` and `admin:write`
scopes, in the same way as the
xref:develop:api/reference/uploads/blobs/upload.adoc[upload mutation]. A token
granted only the participant scopes is rejected, even when the user is an
administrator.

[source,graphql]
----
mutation deleteAttachmentCollection($componentId: ID!, $resultId: ID!, $attachmentCollectionId: ID!){
  component(id: $componentId){
    ... on AccountabilityMutation {
      result(id: $resultId){
        deleteAttachmentCollection(id: $attachmentCollectionId){
          id
        }
      }
    }
  }
}
----

Example of submitted variables

[source,json]
----
{
  "componentId": "3",
  "resultId": "5",
  "attachmentCollectionId": "1234"
}
----

== Error Handling

The most frequent errors that can be generated by this mutation are as follows:

* xref:develop:api/reference/errors/unauthorized_field.adoc[Unauthorized Field Error - UNAUTHORIZED_FIELD_ERROR] - when the token does not have the required scopes
* xref:develop:api/reference/errors/unauthorized_mutation.adoc[Unauthorized Mutation Error - MUTATION_NOT_AUTHORIZED_ERROR]
* xref:develop:api/reference/errors/validation_error.adoc[Validation Error - VALIDATION_ERROR]
* xref:develop:api/reference/errors/unauthorized_object.adoc[Unauthorized Object Error - UNAUTHORIZED_OBJECT_ERROR]
